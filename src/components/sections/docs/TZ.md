# ТЗ: сайт forma-buro.com — MVP

> Рабочее ТЗ для самого себя (Claude) на разработку. Источники: бриф «Express Architectural Concepts» (3 стр.) и сайты-референсы.
> Цель сайта: **собирать квалифицированные заявки** (с файлами и понятным источником), а не просто показывать портфолио.

---

## 0. Контекст бизнеса (из брифа)

**Бренд:** FORMA BURO · домен `forma-buro.com`

**Что продаём**
- Быстрые планировочные концепции
- 3D-модели
- Фотореалистичные визуализации
- PDF-презентации недвижимости
- Отдельно: архитектурные промовидео (Films)

**Главный оффер:** архитектурное решение + быстрая презентация. Не «AI-картинки». Это нужно показывать на каждой странице: план → решение → визуал → презентация.

**Сегменты (5):**
| Сегмент | Боль / задача | Посадочная |
|---|---|---|
| Риелторы / агентства | упаковка объектов под реконструкцию и продажу | `/real-estate` |
| Строители | показать будущий ремонт, усилить КП | `/construction` |
| Девелоперы | оптимизация планировок + маркетинговая упаковка ЖК (2 услуги: Planning / Marketing) | `/developers` |
| Инвесторы | анализ планировочного потенциала до покупки | `/investors` |
| Частные клиенты | экспресс-концепция интерьера до полного проекта | `/homeowners` |

**Рынок:** Лигурия: Санремо, Бордигера, Оспедалетти, Вентимилья.
**Языки:** IT (основной, по умолчанию) → EN. Архитектура i18n должна позволять добавить язык без переделки (позже, возможно, RU/UK/FR).

**Итоговое визуальное направление**
- Минимализм, премиальность, изображение главное. Сетка с большими полями.

- **Не жертвуем скоростью ради эффектов**: это лидогенерационный сайт под рекламный трафик.

## 3. Карта сайта (MVP)

```
/[locale]
├── /                      HOME
├── /real-estate           FOR REAL ESTATE (агентства, риелторы)
├── /construction          FOR CONSTRUCTION (строители)
├── /developers            FOR DEVELOPERS: Planning / Marketing
├── /investors             FOR INVESTORS
├── /homeowners            FOR HOMEOWNERS (частные клиенты)
├── /projects              список кейсов (фильтр по сегменту/услуге)
│   └── /projects/[slug]   страница кейса (шаблон DVDW)
├── /films                 архитектурные промовидео
├── /pricing               цены/пакеты (из CMS)
├── /faq                   FAQ (из CMS, schema.org FAQPage)
├── /start                 START A PROJECT: форма-квиз
├── /thank-you             страница после отправки (событие конверсии)
├── /privacy, /cookies, /terms
└── 404
/studio                    Sanity Studio (закрыт авторизацией)
```

### 3.1 HOME: блоки
1. **Hero**: видео/слайд «план → интерьер», H1-оффер (IT: напр. *«Concept architettonico e presentazione del tuo immobile in pochi giorni»*), подзаголовок, 2 CTA: «Inizia un progetto» и «Guarda i progetti».
2. **Выбор сегмента**: 5 карточек «Я риелтор / строитель / девелопер / инвестор / владелец» → посадочные. Сегмент запоминается (cookie) и подставляется в форму.
3. **Кейсы**: 3–6 избранных; формат **до/после** (слайдер-сравнение план ↔ визуал).
4. **Что вы получаете**: 4 услуги + Films.
5. **Преимущества / отличие от AI-картинок**: архитектурная логика, реальные размеры, нормы, презентация под продажу.
6. **Процесс**: 4–5 шагов (файлы → концепция → 3D → визуал → PDF).
7. **Сроки**: цифры (напр. «концепция за 48–72 ч»; утвердить).
8. **Цены-тизер** → `/pricing`.
9. **FAQ-тизер**.
10. **Финальный CTA + короткая форма** (email + тип клиента → ведёт на полный `/start` с предзаполнением).

### 3.2 Посадочные по сегментам: единый шаблон
Hero под боль сегмента → 2–3 релевантных кейса → что получите (под сегмент) → процесс и сроки → цена «от» → FAQ сегмента → форма с предвыбранным типом клиента.
`/developers`: два явных оффера-таба **Planning** (оптимизация планировок) и **Marketing** (упаковка ЖК), 2 кейса-оффера, отдельный CTA «Запросить B2B-презентацию».

### 3.3 Страница кейса (по образцу DVDW)
- Hero-галерея (2–3 кадра, широкий формат)
- H1 + мета: локация, тип объекта, площадь, сегмент, услуги, сроки выполнения
- Вводный текст (сворачиваемый «Leggi di più»)
- Блок **«Задача → Решение → Результат»** (для продаж важнее, чем «красиво»)
- До/после: исходный план ↔ концепция ↔ визуал
- Галерея с лайтбоксом, счётчик «1/N», свайп на мобильных, клавиатура
- Опц.: встроенное видео, скачать пример PDF (за email = лид-магнит, фаза 2)
- «Altri progetti»: 3 карточки + назад к списку
- CTA «Хочу так же для своего объекта»

## 4. Форма заявки `/start`: главный элемент сайта

Многошаговая (квиз), прогресс-бар, сохранение черновика в localStorage, работает без перезагрузки.

| Шаг | Поля |
|---|---|
| 1. Кто вы | тип клиента* (5 сегментов + «другое»), страна*, город/коммуна (подсказки: Sanremo, Bordighera, Ospedaletti, Ventimiglia…) |
| 2. Объект | тип объекта* (квартира, вилла, дом, коммерция, ЖК/участок), площадь м²*, состояние (под реконструкцию / в ремонте / новостройка) |
| 3. Услуга | нужная услуга* (мультивыбор: планировочная концепция, 3D, визуализации, PDF-презентация, видео), желаемый срок, бюджет (диапазоны, опц.) |
| 4. Файлы | планы / обмеры / фото (drag&drop, PDF/JPG/PNG/HEIC/DWG/ZIP, до 10 файлов, до 50 МБ каждый), комментарий; **до 5 доп. вопросов**, зависят от сегмента (настраиваются в CMS) |
| 5. Контакты | имя*, email*, телефон, мессенджер (WhatsApp / Telegram / другое + ник), предпочтительный язык, **согласие GDPR*** (отдельный чекбокс маркетинга, не обязательный) |

**Обработка (сервер):**
1. Валидация zod на клиенте и сервере, Turnstile.
2. Файлы → Vercel Blob (прямая загрузка с клиента, подписанные URL).
3. Запись лида: Sanity-документ `lead` (или Google Sheet) — **источник правды, чтобы ничего не терялось**, даже если email упал.
4. Email команде (Resend): все поля + ссылки на файлы + **метки источника**.
5. Email клиенту: подтверждение получения на его языке + что дальше и в какие сроки.
6. Webhook в CRM (адаптер, включается env-переменной).
7. Редирект на `/thank-you` → событие `generate_lead` в dataLayer (с `client_type`, `service`, `locale`).

**Метка источника (атрибуция):** при первом заходе сохраняем в first-party cookie (90 дней) `utm_source/medium/campaign/term/content`, `gclid`, `fbclid`, `referrer`, landing page, и last-touch отдельно. Всё прикладываем к лиду.

**Квалификация:** авто-скоринг (сегмент B2B, площадь, наличие файлов, бюджет) → поле `lead_score` и тег `qualified`/`unqualified` в письме/CRM.

## 5. CMS (Sanity): схемы

- `project`: title*, slug, сегменты[], услуги[], локация, тип объекта, площадь, год, клиент (опц.), сроки, задача/решение/результат, hero-изображения, галерея, пары до/после, видео, featured, SEO-поля. **Все текстовые поля локализованы (it/en).**
- `film`: название, видео, постер, описание, проект-ссылка.
- `service`: название, описание, что входит, сроки, цена «от».
- `pricingPlan`: пакет, цена/«от», что входит, сегменты, CTA.
- `faq`: вопрос/ответ, сегменты[], порядок.
- `segmentPage`: тексты посадочных (hero, боли, блоки), выбор кейсов и FAQ.
- `formConfig`: доп. вопросы по сегментам (до 5), списки опций.
- `siteSettings`: контакты, мессенджеры, соцсети, тексты футера, цифры-статистика.
- `lead`: только чтение в Studio (архив заявок).

Публикация из Studio → webhook → on-demand revalidation (ISR) на Vercel.

## 6. Аналитика и согласия

- GTM-контейнер; GA4 через GTM. Meta Pixel + Conversions API (фаза 2, если пойдёт Meta-реклама). Google Ads conversion + Enhanced Conversions.
- **Consent Mode v2**: по умолчанию всё `denied`, до согласия трекинг не грузится (требование ЕС/Италии, Garante).
- События dataLayer: `form_start`, `form_step` (номер шага), `file_upload`, `generate_lead`, `cta_click` (позиция), `segment_select`, `video_play`, `messenger_click`, `phone_click`, `email_click`.
- Раздельная отчётность по сегментам: `client_type` как custom dimension.
- Для теста 30–45 дней: стоимость лида, квалифицированного лида, оплаченного заказа (последнее через статус в CRM).

## 7. SEO и производительность

- SSG/ISR для всех страниц, `next/image` + Sanity CDN (AVIF/WebP), lazy-load галерей.
- **Lighthouse mobile ≥ 90** (Performance, Accessibility, SEO, Best Practices); LCP < 2.5 с на 4G. Hero-видео: постер сразу, видео после загрузки, на мобильных облегчённое/статичное.
- hreflang it/en + x-default, sitemap.xml, robots.txt, canonical, OG-изображения (генерация через `next/og`).
- Schema.org: `Organization`/`ProfessionalService` (areaServed: Лигурия), `FAQPage`, `CreativeWork` для кейсов, `BreadcrumbList`.
- Локальное SEO: упоминание коммун в текстах посадочных, Google Business Profile (вне сайта).
- Доступность: skip-links, фокус-стейты, alt из CMS (обязательное поле), контраст AA, навигация с клавиатуры в лайтбоксе и квизе.

## 9. Git + Vercel: настройка

```bash
# 1. Репозиторий
npx create-next-app@latest forma-buro-web --ts --tailwind --app --src-dir --eslint
cd forma-buro-web
git init && git add -A && git commit -m "chore: init Next.js"
gh repo create forma-buro-web --private --source=. --push

# 2. Vercel
npx vercel login
npx vercel link            # создать проект forma-buro-web
# Git-интеграция: Vercel → Project → Settings → Git → подключить GitHub-репо
# → Production branch: main; Preview на каждую ветку/PR

# 3. Домен
npx vercel domains add forma-buro.com
npx vercel domains add www.forma-buro.com   # редирект www → apex
# DNS у регистратора: A @ → 76.76.21.21, CNAME www → cname.vercel-dns.com
# (или перенести NS на Vercel)

# 4. Хранилище
npx vercel blob store add forma-buro-uploads   # BLOB_READ_WRITE_TOKEN появится в env
```

**Переменные окружения** (Vercel → Settings → Environment Variables, локально `.env.local`, в репо `.env.example`):
```
NEXT_PUBLIC_SITE_URL=https://forma-buro.com
NEXT_PUBLIC_SANITY_PROJECT_ID=
NEXT_PUBLIC_SANITY_DATASET=production
SANITY_API_READ_TOKEN=
SANITY_API_WRITE_TOKEN=        # запись лидов
SANITY_REVALIDATE_SECRET=
BLOB_READ_WRITE_TOKEN=
RESEND_API_KEY=
LEADS_EMAIL_TO=
LEADS_EMAIL_FROM=hello@forma-buro.com   # домен верифицировать в Resend (SPF/DKIM)
NEXT_PUBLIC_GTM_ID=
NEXT_PUBLIC_TURNSTILE_SITE_KEY=
TURNSTILE_SECRET_KEY=
CRM_WEBHOOK_URL=               # опционально
```

**Процесс:**
- Ветки: `main` (прод), `feat/*`, `fix/*`. Conventional Commits.
- Каждый PR → Preview URL Vercel → проверка → merge → авто-деплой в прод.
- GitHub Actions: `lint`, `typecheck`, `build` на PR. Опц.: Lighthouse CI на preview.
- Prettier + ESLint, husky + lint-staged.

**Структура проекта:**
```
src/
  app/[locale]/(site)/...      страницы
  app/api/lead/route.ts         приём заявки
  app/api/upload/route.ts       токены Blob
  app/api/revalidate/route.ts   webhook Sanity
  app/studio/[[...tool]]/       Sanity Studio
  components/ (ui, sections, form, gallery, media)
  lib/ (sanity, i18n, analytics, utm, leads, email)
  messages/it.json, en.json     UI-строки
sanity/schemas/                 схемы CMS
```

## 11. Критерии приёмки

- [ ] Заявка с 5 файлами по 20 МБ доходит **без потерь**: файлы доступны по ссылкам, лид есть в архиве, письмо команде и подтверждение клиенту пришли.
- [ ] У каждого лида видны: сегмент, услуга, UTM/gclid/fbclid, landing page, referrer, язык, score.
- [ ] Если Resend недоступен, лид всё равно сохраняется (проверено).
- [ ] `generate_lead` фиксируется в GA4 только после согласия; до согласия трекеры не грузятся.
- [ ] Кейсы, цены, FAQ, тексты посадочных и переводы редактируются в CMS без разработчика; изменения на сайте ≤ 1 мин.
- [ ] IT и EN полностью, hreflang корректен.
- [ ] Lighthouse mobile ≥ 90 на HOME, посадочной, кейсе, `/start`.
- [ ] Адаптив 360 / 768 / 1280 / 1920; iOS Safari, Chrome Android, desktop Chrome/Safari/Firefox.
- [ ] Privacy, Cookie Policy, GDPR-согласие в форме; данные хранятся в ЕС, где возможно (регион Sanity/Blob).
- [ ] Preview-деплой на каждый PR, прод с `main` на `forma-buro.com` по HTTPS.

## 12. Открытые вопросы (уточнить у заказчика)

1. Финальное название и логотип: «FORMA BURO» / «Forma Buro»? Есть ли фирменный стиль, шрифты?
2. Какая CRM (HubSpot / Pipedrive / Bitrix / пока только email)?
3. Реальные кейсы: сколько есть, исходники (план + визуал + PDF), можно ли называть локации и клиентов?
4. Цены: показываем точные пакеты или «от»? В EUR с НДС/без?
5. Сроки, которые обещаем (концепция за X часов/дней)?
